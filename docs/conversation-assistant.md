# 对话助手

## 直接摘录，复制到 GPT

在“对话助手”点击“提取当前对话”，然后正常切回微信主窗口打开目标单聊，或点开普通的独立聊天窗口。一次性提取会等待可核实的微信窗口，因此无需提前输入联系人名、固定窗口或发送新消息。也可以显式开启切回微信时的本地自动预览。提取使用当前打开聊天区的标题和消息列表；本机排除名单同样适用。

预览按微信里的顺序显示，例如：

```text
微信对话：示例单聊
范围：当前可见片段（2 条文字）

[对方] 之前提到的合同，哪天可以一起看？

[我] 周五下午可以。
```

可以复制预览文字，也可以另存为普通 UTF-8 文本。对于旧话题，先在微信里滚动到相关消息再提取；对于之前已经记录的聊天，可以用“预览全部本机记录”，再从预览中选中想交给 GPT 的旧段落并复制。导出保留多行文本、重复消息和已有的间断标记，无法确定发言方的行会标作“方向未确认”。一次可见片段只覆盖微信当前提供的文字行。

自动预览在进入一个可核实的会话时读取一次，同一个窗口持续停留时不会反复采集。切回 AppShield 后保留刚才的预览。已能识别的群聊标识和本机排除项会阻止提取；部分版本只提供标题和聊天区结构，无法据此独立确认联系人身份或会话类型，复制前应核对标题与内容。

摘录与导出无需配置 OpenAI。复制后由用户决定是否粘贴到第三方；另存为的文件是明文，保存位置由用户选择。

## 可选的持续记录与 API 起草

1. 在 AppShield 选择已导入的微信，打开“对话助手”，选择文件传输助手，或输入本人/指定单聊在微信中的准确显示名。窗口标题、进程归属和消息列表均由 AppShield 的 Windows 采集器核实；日常运行不需要 Computer Use。
2. 开启预览，将对应的微信聊天区切到前台，或在微信中置顶该对话的独立窗口。AppShield 核对微信进程、目标窗口、聊天标题与消息列表。第一批内容停留在预览中，确认后才写入本机。无法可靠辨认消息区时，可以手动输入或自行粘贴选段。微信受限剪贴板模式可能影响复制操作。
3. 相邻可见片段按顺序对齐。采集中断、重开窗口或无法唯一对齐时保留分段。方向首先依据已核实的气泡或文字控件位置。遇到微信 4.2 暴露整行、没有文字几何的情况，程序可在该可见文字行内抽样左右气泡边缘与背景，核对取样点属于同一窗口；不保存图像，颜色数据不发送到 API。窗口被挡住、主题或位置证据不足时保留“方向未知”。本地记录只包含用户确认范围内的可见内容或手动输入。
4. 手动模式下，填写本次意图，预览发给 GPT 的内容，再确认生成。若希望助手主动建议，在确认来源后为这个对话勾选自动备稿，即授权它在后续可靠的新来信到达后自动提交本轮消息、最近的连续上下文和回复意图。
5. 自动模式先读取基线，已有消息不触发。连续来信合并，距最后一次来信约十秒且再次确认来源后才调用 API。本轮只提交一次；本人已回复、方向不明、发现新的记录缺口或来源无法核实时取消待处理任务。暂停或切换目标会撤销本次授权。聊天内容作为引文；模型返回可编辑的回复、需要用户确认的问题或“无需回复”的提示。后两种只显示在助手内；新结果不会覆盖用户手改的草稿。

## 每人使用自己的 OpenAI 密钥

AppShield 在生成草稿时读取密钥。优先使用界面密码框中仅供本次会话使用的输入，其次查同名的进程环境变量和当前 Windows 用户环境变量。默认变量名为 `OPENAI_API_KEY`，默认模型为 `gpt-6-luna`。

源码构建可以使用被 Git 忽略的 `.local/conversation-assistant.json`。单独分发程序时，用户可在 `%LOCALAPPDATA%\AppShield\conversation-assistant.json` 覆盖默认设置。配置只接受模型名和两种已知环境变量名（`OPENAI_API_KEY`、`APPSHIELD_OPENAI_API_KEY`）。无需把密钥写入 JSON、程序源码或构建产物。

```json
{
  "apiKeyEnvironmentVariable": "OPENAI_API_KEY",
  "model": "gpt-6-luna"
}
```

调用使用固定的 OpenAI HTTPS Responses 接口、禁用自动重定向，并设置 `store: false`。API 请求必须在本机进程内存中构造身份验证请求头。Windows 环境变量对相应用户权限下的程序可读；环境变量名配置解决的是源码、配置分发和日志泄密问题。会话密钥输入不会被 AppShield 写入本地历史。

## 本机排除名单

如需排除对话，可以在上述同样的私有设置位置创建 `conversation-exclusions.json`，内容是显示名的 JSON 字符串数组。匹配采用规范化后的精确名称、忽略大小写；两个位置的排除项均生效。公开仓库不携带个人联系人名单。确认新的绑定前应当检查目标及首批预览。

## 开发验证

常规 `.\tools\Build-AppShield.ps1 -Test` 使用虚构对话和模拟 HTTP 响应。另可用 `DesktopChecks.exe --conversation-uia-fixture` 和 `--conversation-panel` 运行窗口与交互验收；`--conversation-auto-gpt-synthetic` 使用虚构的两条来信、真实静默计时和本机 API 密钥，验证应用自主发起一次真实请求并显示草稿。真实手机联测由用户选择测试对话，可只匹配约定的标记。微信 4.2.0.53 的置顶文件传输助手已由产品采集器连续两次命中同一标记。手机自发消息的这次同步中，用户未观察到桌面横幅。

本轮产品采集器也连续两帧按正确顺序读到这两条授权文字。真实 UIA 提供的是全宽行，几何证据单独给出的方向为未知；补充的气泡窄带判断仍待真实窗口复核。自动备稿的真实 API 对照使用合成来信，两个连续静默周期只生成一条草稿。真实对方来信在微信中触发 API 的整条链路仍待另行联测。
